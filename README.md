# NaviJSON

NaviJSON is a Mapbox-compatible cartography and navigation project. The first exposed experience is **California Light**, an independently designed, Apple-inspired light map backed by the NaviJSON Reality Layer, an OpenStreetMap-derived enrichment of real California geography.

## California Light

Open the app at:

```text
/maps/GeoJSON/A_M-light
```

Direct assets:

- `/maps/GeoJSON/A_M-light/style.json`
- `/maps/GeoJSON/A_M-light/features.geojson`
- `/maps/GeoJSON/A_M-light/tokens.json`

The experience works without credentials through a built-in interactive canvas renderer. Add `NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN` to `.env.local` to switch the same route to Mapbox GL JS and the Mapbox Standard basemap.

## Local setup

```bash
npm install
npm run dev
```

Then open the local URL shown by the development server. Copy `.env.example` to `.env.local` only when enabling live Mapbox mode.

## Checks

```bash
npm run build
npm run lint
npm test
```

The test suite verifies the requested route, root redirect, the enriched GeoJSON Reality Layer (size, feature-type coverage, road paint, grade separation, and per-feature provenance), design tokens, and Mapbox style structure.

## Reality Layer data

The bundled `features.geojson` is no longer a hand-drawn fixture. It is a real **NaviJSON Reality Layer** generated by `scripts/pipeline/` from **OpenStreetMap** — ~105,000 features carrying a per-feature provenance envelope (`source`, `source_ref`, `license: "ODbL"`, and a `confidence` score). The committed sample spans **15 dense California regions** — SF Financial District, Oakland + the MacArthur Maze, San José + the I-280/CA-87 interchange, Sacramento, Fresno, downtown/interchange Los Angeles (including the Judge Harry Pregerson four-level stack), Santa Monica, Pasadena, Long Beach, and San Diego + the I-15/I-8 interchange.

The **entire state of California** is delivered as a vector-tile tileset (16.98M features, zoom 4–16) built from the full California OSM extract — see [`docs/STATEWIDE_TILESET.md`](docs/STATEWIDE_TILESET.md).

The layer includes roads (ranked by hierarchy), **road paint** (`lane_divider` lane markings, including double-yellow centerlines), buildings, water and parks, rail, sidewalks and paths, traffic signals, stop signs and other traffic signs, **light poles** (`street_lamp`), pedestrian crossings, and **grade-separated overpasses/underpasses** (`bridge`/`tunnel`/`layer`).

The data is © OpenStreetMap contributors and distributed under the Open Database License (ODbL). See [`docs/SCHEMA.md`](docs/SCHEMA.md) for the full feature contract.

### Regenerate

```bash
node scripts/pipeline/build-region.mjs            # rebuild all committed regions
```

### Add a region

Add an entry under `committed` in `scripts/pipeline/regions.json` (an `id`, `name`, and a `bbox`), then generate it directly by bounding box:

```bash
node scripts/pipeline/build-region.mjs --bbox W,S,E,N --id my-area
```

Sample regions are fetched from the free public Overpass API; the statewide extent is produced offline from a Geofabrik California PBF (see [`docs/A_M_LIGHT.md`](docs/A_M_LIGHT.md)).

## Data boundary

Reality Layer data must come from open, public-domain, customer-provided, or explicitly licensed sources and include provenance and confidence. The committed layer satisfies this via OpenStreetMap (ODbL). Restricted commercial services (Google, Apple, and similar) must not be used for feature extraction without written derivative-data rights.

See [California Light documentation](docs/A_M_LIGHT.md), [the feature schema](docs/SCHEMA.md), [the statewide tileset](docs/STATEWIDE_TILESET.md), [data licenses](docs/DATA_LICENSES.md), and [costs](docs/COSTS.md).
