# NaviJSON California Light (`A_M-light`)

The public map route is `/maps/GeoJSON/A_M-light`.

## Public assets

- `/maps/GeoJSON/A_M-light/style.json` — Mapbox Style Specification v8 document
- `/maps/GeoJSON/A_M-light/features.geojson` — the OpenStreetMap-derived (ODbL) Reality Layer for the committed California sample regions
- `/maps/GeoJSON/A_M-light/tokens.json` — cartographic design tokens and minimum zooms

The style imports Mapbox Standard and places the NaviJSON detail through the `bottom`, `middle`, and `top` slots. It is Apple-inspired in clarity and restraint, but it is independently designed and uses no Apple assets.

## Mapbox mode

Copy `.env.example` to `.env.local` and add a public Mapbox token. The route automatically switches from the built-in no-key canvas renderer to Mapbox GL JS.

```text
NEXT_PUBLIC_MAPBOX_ACCESS_TOKEN=pk.your_public_token
```

The token is intentionally not committed. Restrict the public token to the domains that will host NaviJSON.

## No-key mode

Without a token the same route renders an interactive California Light preview from `features.geojson`. Pan by dragging, zoom with the wheel or a double-click, and change the dawn/day/dusk preset in the lower-right control.

## Reality Layer feature set

The served `features.geojson` is a real Reality Layer, not a hand-drawn fixture. It is generated by `scripts/pipeline/build-region.mjs` from **OpenStreetMap** (© OpenStreetMap contributors, ODbL) for the committed California sample regions and contains thousands of features. Every feature carries a provenance envelope (`source: "openstreetmap"`, `source_ref`, `license: "ODbL"`, `confidence`, `observed`, `region`). The full contract is in [`docs/SCHEMA.md`](SCHEMA.md).

Feature categories include:

- **Roads** — ranked by hierarchy (`rank` 1–8), with lanes, oneway, surface, and speed.
- **Road paint** — `lane_divider` lane markings derived from lane counts (double-yellow `centerline`s and white-dashed `lane_line`s).
- **Grade separation** — overpasses and underpasses via `bridge`, `tunnel`, and `layer`. The `guadalupe-i280-87-interchange` region is committed specifically to exercise this.
- **Buildings** with heights, **water** and **parks**, **rail**, **sidewalks**, **paths**, and **cycleways**.
- **Point furniture** — traffic **signals**, **stop signs** and other traffic signs, **light poles** (`street_lamp`), and pedestrian **crossings**.

## Pipeline and regions

Regions are defined in `scripts/pipeline/regions.json`. The `committed` entries (Downtown San José and the I-280/CA-87 interchange) are small representative extracts fetched from the free public Overpass API and checked in. Regenerate them with:

```bash
node scripts/pipeline/build-region.mjs                    # all committed regions
node scripts/pipeline/build-region.mjs --bbox W,S,E,N --id my-area
```

## Statewide California

The `statewide` entry in `regions.json` holds the full California bounding box. The whole-state extent is **not** built from a live Overpass call and its raw output is **not** committed. Instead it is produced offline from a downloaded **Geofabrik California `.osm.pbf`** extract, transformed into the NaviJSON schema, and run through **tippecanoe** to produce vector tiles / **PMTiles**. That hosted tileset is then pointed at by the `navijson-reality` source (replacing the committed sample GeoJSON) once it is published. This keeps the repository light while giving a documented path from the sample regions to statewide coverage.
